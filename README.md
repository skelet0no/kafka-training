# Изучение Kafka

Учебный проект для изучения Apache Kafka


>[!IMPORTANT]
> Это самое первое знакомство с Kafka, основное изучение происходит в реальных проектах. Этот репозиторий просто старт + небольшие вещи, которые было интересно посмотреть
> лично мне


## Архитектура

Producer -> Kafka Broker -> Consumer

## Компоненты

- Продюсер на питоне
- Консьюмер на питоне
- Кафка брокер

## Запуск

### Терминал 1
Запуск кафки
```angular2html
docker compose up -d
docker exec kafka /opt/kafka/bin/kafka-topics.sh --create --topic events --bootstrap-server localhost:9092
docker stats
```

### Терминал 2
Запуск консьюмера
```angular2html
python consumer/consumer.py
```

### Терминал 3
Запуск продюсера
```angular2html
python producer/producer.py
```

## Исследования
В начале каждого исследования брокер, консьюмер и продюсер включены
### 1. Остановка консьюмера
#### Действия
1. Остановить consumer
2. Отправить сообщение через продюсер
3. Включить консьюмер

#### Результат
После подключения консьюмера к брокеру все не полученные сообщения по очереди отобразились в консьюмере

### 2. Работа offset
#### Действия
1. Отправить сообщение
2. Остановить консьюмер и продюсер
3. Запустить консьюмер и продюсер
4. Отправить сообщение
5. Проверить offset

#### Результат
После отправки сообщений видно, что offset продолжается с того с числа 1. То есть он продолжает чтение

### 3. Два консьюмера (Разные group.id)
#### Действия
1. Запустить второй консьюмер с другим `group.id`
2. Отправить сообщение

#### Результат
Второй консьюмер восстановил всю историю сообщений (благодаря 'auto.offset.reset': 'earliest'). Отправленные сообщения попадают в обе группы консьюмеров

### 4. Запуск топика с двумя partitions
#### Действия
1. Создать новый топик с флагом `--partitions 2`
2. Подключить топик в консьюмер и продюсер
3. Отправить несколько сообщение

#### Результат
Часть сообщений отправилась с partition=0, а часть с partition=1. Это автоматическое распределение между доступными partitions

### 5. Два консьюмера (PartitionCount: 2)
#### Действия
1. Создать новый топик с флагом `--partitions 2`
2. Подключить топик в консьюмер и продюсер
3. Запустить второй консьюмер 
4. Отправить несколько сообщение

#### Результат
Все сообщения с partition=0 попадают в первый консьюмер, а все сообщения с partition=1 попадают во второй консьюмер

#### Дополнение
2 консьюмера, 3 partition -- сообщения с 0 и 2 partition попадают в один консьюмер, сообщения с partition 1 в другой

3 консьюмера, 2 partition -- сообщения с partition=0 попадают в первый консьюмер, с partition=2 во второй. Третий консьюмер пустой

Если при 2 активных консьюмеров остановить 1, то произойдет балансировка и оставшийся консьюмер возьмет на себя оба partition
